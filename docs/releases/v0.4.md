## Scope

This release turns the two remaining untyped boundaries into declared contracts.
Query execution becomes a tool with a typed result, and every model call returns
a value paired with what the call cost.

Expected outcomes become values. Only a programming error still raises.

The model also gains two structured ways to decline, so it is no longer forced
to produce SQL for a question it cannot answer.

No persistence, memory, streaming, hosted deployment, or user interface. No
Azure resources changed, and every capability flag introduced in v0.1 is still
`false`.

## What shipped

`database/tool.py` is the new module. It declares `QueryTool`, one operation
`execute`, and `QueryToolResult` carrying a four-case status.

| Status | Meaning |
| --- | --- |
| `success` | The statement ran and matched rows |
| `empty` | The statement ran and matched nothing |
| `rejected` | The boundary refused to run it |
| `failed` | Execution was attempted and did not complete |

`QueryToolResult.__post_init__` refuses a value that contradicts its own status,
so a caller cannot read rows from a refusal or a reason from a success. Fakes
implement the same contract, so the invariant is checked in the dataclass rather
than trusted at each construction site.

`agents/model.py` gained `ModelConfiguration`, resolved once and passed
explicitly, and `ModelInvocation`, which pairs every returned value with
`ModelCallMetadata`. Structured output moved to `json_schema`, which is
constrained decoding against the schema rather than a prompt asking for JSON.

Three constants encode facts that should change with a reviewed diff rather than
per environment: `STRUCTURED_OUTPUT_METHOD`, `SUPPORTS_TEMPERATURE`, and
`MAX_MODEL_RETRIES`. The middle one is `False` because recent
reasoning-oriented deployments reject an explicit sampling temperature and fail
the whole request. The last is transport-only, because retrying a malformed
answer would hide an attempt the repair budget is meant to bound.

`agents/state.py` gained `GenerationDisposition` with `ready`,
`clarification_required`, and `unsupported`. `AgentOutcome` grew to six terminal
states, adding `empty`, `clarification_required`, and `unsupported` to the
success, rejection, and failure cases that already existed.

The terminal node is now `finalize` rather than `fail`, because a run that ends
without rows is not necessarily a failure. Routing functions went from three to
four.

`docs/roadmap.md` was removed in this release. Release notes and architecture
notes describe what shipped and what was deferred, and a separate forward-looking
plan had begun to contradict them.

## Measurements

| Measure | v0.3 | v0.4 | Unit |
| --- | --- | --- | --- |
| Graph nodes | 7 | 7 | count |
| Routing functions | 3 | 4 | count |
| Terminal outcomes | 2 | 6 | count |
| Ways the model may decline | 0 | 2 | count |
| Query tool statuses | not modelled | 4 | count |
| Offline tests | 238 | 290 | count |
| Integration tests | 14 | 19 | count |

The outcome count is the number worth reading. A caller that can only
distinguish success from failure reports an outage every time a filter is narrow,
because `empty` and `failed` look identical.

## Verification

```console
uv run pytest -m "not azure"
uv run pytest -m azure
uv run ruff check .
uv run mypy src scripts
```

Notebook `03_model_and_tool_contracts.ipynb` walks both contracts with scripted
dependencies, so the outcomes can be exercised without a model deployment or a
database.

## Limitations

The agent still runs in whatever process starts it and authenticates as whoever
started it. It has no image, no identity, and no protocol surface.

Model call cost is recorded but not aggregated. `ModelCallMetadata` carries
latency and purpose per call, and nothing yet rolls that into a per-run total.

Token counts are not captured. Latency is measured at the boundary, but the
release records no evidence about token consumption or spend.

Deployment, identity, and protocol are v0.5.
