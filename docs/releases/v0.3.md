## Scope

This release migrates the Text-to-SQL agent onto LangGraph 1.2 as an explicit
`StateGraph` with typed state, deterministic read-only validation, one bounded
repair attempt, and structured success or failure output.

The model is no longer an actor. It has no tools, it never executes anything,
and it makes no routing decision. It drafts SQL, corrects SQL once, and
describes rows that have already been retrieved.

No persistence, memory, streaming, hosted deployment, FastAPI, user interface,
MCP, or Foundry IQ. No Azure resources changed, and every capability flag
introduced in v0.1 is still `false`. Checkpointing moves to v0.8 deliberately:
adding durability to a graph whose control flow was not yet testable would have
made both harder to verify.

## What shipped

A sixth boundary, `agents/`, with five modules:

| Module | Responsibility |
| --- | --- |
| `state.py` | Typed input, internal state, output, and the node and failure enumerations |
| `graph.py` | Topology, three pure routing functions, and compilation |
| `nodes.py` | The seven node implementations and their explicit dependencies |
| `model.py` | The only place that builds a chat client or parses a model response |
| `prompts.py` | Drafting, repair, and answering prompts |

The graph has seven nodes and thirteen edges. The legacy graph had two nodes,
`agent` and `tools`, and three edges, and its shape said nothing about what the
agent would actually do because the model chose the path at run time.

`errors.py` gained `ModelOutputError`, the sixth named error, raised when a
response does not satisfy the expected schema.

`config/settings.py` gained `AZURE_FOUNDRY_ACCOUNT_ENDPOINT` and
`AZURE_OPENAI_API_VERSION`. The project endpoint and the account endpoint are
different hosts, so both are kept rather than one being derived from the other.

`database/queries/04_schema_context.sql` renders every user table with column
types, nullability, primary keys, and foreign key targets. It passes the same
read-only validator that agent-generated SQL passes.

## Before and after

Captured by `notebooks/02_modern_langgraph_text_to_sql.ipynb` and written to
[v0.3-measurements.json](v0.3-measurements.json).

| Measure | Before | After | Unit |
| --- | --- | --- | --- |
| Graph nodes | 2 | 7 | count |
| Graph edges | 3 | 13 | count |
| Model calls, happy path | 4 | 2 | count |
| Model calls, repair path | unbounded | 3 | count |
| Maximum statements the model may write | unbounded | 2 | count |
| Unsafe statements blocked before execution | 0 | 2 of 2 | count |
| Offline tests | 213 | 238 | count |
| Offline test duration | 11.4 | 24.0 | s |
| Integration tests | 9 | 14 | count |
| Happy path graph overhead | not measured | 78.8 | ms |
| Repair path graph overhead | not measured | 58.6 | ms |

Two numbers deserve explanation rather than celebration.

The node and edge counts went up, and that is the point. The legacy graph was
small because the model made the decisions the edges now make. Complexity was
not removed; it was moved from run time into a shape that can be read and
tested.

Offline test duration doubled. The suite grew by 25 tests, several of which
compile and stream a graph. Twenty-four seconds for a suite that needs no cloud
access remains a usable inner loop.

## Measurement definitions

**Model calls, happy path.** Calls to the model for one answered question with
no repair. Two: one draft, one answer. The legacy baseline of four counts
`list_tables`, `get_schema`, the draft, and the answer, and it is a floor rather
than a fixed cost because the model could call the inspection tools again.

**Model calls, repair path.** The same question when the first statement is
rejected. Three: draft, repair, answer.

**Unsafe statements blocked before execution.** Statements rejected by
`assert_read_only_sql` that never reached the driver, out of the number the model
produced. Measured with a scripted model that returns `DELETE` twice.

**Graph overhead.** Wall time for one `answer_question` call with a scripted
model and a scripted database. It measures the graph, not the model, and is not
comparable to end-to-end latency.

**Happy path latency.** End-to-end wall time against the deployed model and
database. Recorded as `null` in this release because the ODBC driver is absent
on the machine that captured the measurements.

```console
uv run pytest -m azure              # 1 passed, 13 skipped
uv run ruff check .

```

The notebook runs offline end to end. Its live cell reports why it skipped
rather than failing.

## Known limitations

**The ODBC driver is still absent locally.** Thirteen of the fourteen Azure
tests skip, and the live notebook cell skips with
`DatabaseConnectionError: The 'ODBC Driver 18 for SQL Server' ODBC driver is not
installed.` Nothing in `agents/` has therefore executed against the real
database. Install with `winget install --id Microsoft.msodbcsql18` and rerun
`uv run pytest -m azure` to close this.

**The model contract is pinned, not discovered.** `agents/model.py` fixes the
structured-output method as schema-constrained and records that the deployment
does not accept an explicit temperature. Those constants have not yet been
confirmed against `gpt-5.4-mini`, because confirming them requires the
integration suite above. `test_the_deployed_model_honours_the_structured_output_contract`
is the check that will confirm or refute them.

**The validator matches keywords.** A legitimate query containing a forbidden
word inside a string literal is refused. Refusing a valid query is a worse
experience than allowing one, and a much better failure than the reverse.

## Not in this release

Checkpointing and persistence, conversation memory, streaming, an evaluation
runner, tool design, a command line entry point for asking questions, and any
change to Azure infrastructure. Deterministic evaluation is v0.4; durable
checkpointing is v0.8, after hosted execution and observability are measurable.
